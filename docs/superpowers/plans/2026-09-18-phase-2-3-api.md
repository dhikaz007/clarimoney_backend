# ClariMoney Phase 2/3 API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add unified income/expense transactions, category lifecycle, filtering, net cash flow, and deterministic comparison APIs.

**Architecture:** Migrate existing expense data into a unified transaction model. Add category type/status/origin. Build Phase 2 CRUD and summary first; build Phase 3 comparison queries on shared period and category aggregation helpers.

**Tech Stack:** Dart Frog, PostgreSQL/Neon, PostgreSQL numeric/timestamptz, existing auth middleware.

## Global Constraints

- Income also requires category.
- Income and expense categories remain separate by category type.
- Dates use full ISO-8601 with `T`, timezone, and milliseconds where emitted.
- Amounts remain positive magnitudes.
- Existing expense rows backfill as `expense`.
- Phase 3 starts only after Phase 2 migration/API tests pass.

---

### Task 1: Unified transaction/category migration

**Files:** Create `migrations/009_phase2_unified_transactions.sql`; update migration docs; add migration tests.

- Add transaction type, note, nullable category migration path.
- Backfill existing transactions as expense.
- Add category type/status/origin and income starter categories.
- Enforce type/category compatibility, positive numeric amount, note max 500, category lifecycle constraints.
- Add indexes for owner/type/date/search paths.
- Apply Neon migration and verify old records.

### Task 2: Phase 2 transaction/category APIs

**Files:** Update transaction/category routes/services/tests/docs.

- Accept income and expense bodies.
- Require category for both; enforce matching category type.
- Parse full ISO-8601 dates and emit full ISO strings.
- Add note trim/limit behavior.
- Add transaction detail endpoint.
- Add search/type/period/category filters with AND semantics and deterministic ordering.
- Add category rename/archive/reactivate endpoints with ownership checks.
- Preserve old expense-client compatibility during migration window.

### Task 3: Phase 2 summary

**Files:** Update summary route/services/tests/docs.

- Return income total, expense total, net cash flow availability/value.
- Preserve expense breakdown/largest category.
- Implement empty, expense-only, income-only, and full-data states.
- Test numeric precision and UTC period boundaries.

### Task 4: Phase 3 comparison engine

**Files:** Create comparison service/helpers/tests.

- Derive full/partial equivalent comparison period.
- Aggregate income, expense, net cash flow, category values.
- Compute absolute change.
- Compute percentage only for non-zero valid baselines.
- Preserve missing vs zero and net cash flow availability semantics.
- Rank maximum three change drivers by absolute magnitude.

### Task 5: Phase 3 comparison routes

**Files:** Create comparison routes/tests/docs/Bruno requests.

- Add overview comparison endpoint.
- Add category comparison endpoint.
- Add category detail comparison endpoint.
- Enforce auth ownership and persistent category identity.
- Return full ISO period ranges and deterministic JSON shape.

### Task 6: Verification and rollout

- Run ordered migrations 009+ against Neon.
- Run Neon-backed tests with zero skips.
- Run analyzer/build/release migration verifier.
- Update API docs and Bruno collection.
- Push commits after review.
